# Telegram-бот «Формулы Excel» — MVP

Бот принимает задачу обычным текстом и возвращает формулу в двух вариантах
(русский Excel с «;» и английский с «,») плюс объяснение. Второй режим —
«Проверить формулу»: пользователь присылает свою формулу с текстом ошибки,
бот объясняет причину и присылает исправленный вариант.

Реализовано по ТЗ «Telegram-бот "Формулы Excel" — MVP SaaS».
**Эквайринг сознательно не подключён** — см. раздел «Оплата».

## Быстрый старт

```bash
cp .env.example .env     # заполнить BOT_TOKEN, ANTHROPIC_API_KEY, WEBHOOK_BASE, ADMIN_IDS
docker compose up -d --build
docker compose logs -f bot
```

Контейнер при старте сам прогоняет `alembic upgrade head` и поднимает uvicorn на
порту 8080. Наружу порт публикуется только на 127.0.0.1 — перед ним должен стоять
nginx с TLS, потому что Telegram шлёт вебхук только на https.

Вебхук выставляется автоматически при старте на `${WEBHOOK_BASE}/tg/${WEBHOOK_SECRET}`.
`WEBHOOK_SECRET` — это и путь, и значение заголовка `X-Telegram-Bot-Api-Secret-Token`:
чужой POST до диспетчера не дойдёт.

### Локально, без Docker

```bash
pip install -r requirements-dev.txt
make migrate           # нужны поднятые PostgreSQL и Redis
make run               # uvicorn на :8080
make test              # тесты, внешние сервисы не нужны
make lint
```

## Архитектура

```
Telegram → POST /tg/<secret> (FastAPI) → aiogram Dispatcher → FormulaFlow
                                                                 ├─ RateLimiter (Redis)
                                                                 ├─ лимит месяца (PostgreSQL)
                                                                 ├─ ClaudeService (Claude API)
                                                                 └─ запись в requests
```

- `app/main.py` — FastAPI, вебхук, сборка зависимостей, выставление вебхука и меню команд.
- `app/bot/service.py` — сценарий целиком: лимиты → модель → БД. Возвращает
  `Answered | Paywall | RateLimited | Failed`, хендлеры только отрисовывают результат.
- `app/services/claude_client.py` — вызов Claude API и разбор ответа.
- `app/services/prompts.py` — системный промпт и сборка сообщения.
- `app/db/` — модели и репозиторий (все запросы к БД).
- `app/payments/` — интерфейс провайдера оплаты и заглушка.

Решения, которые стоит держать в голове:

- **Системный промпт неизменен** и помечен `cache_control` — это стабильный префикс
  для prompt caching. Всё переменное (режим, «другой вариант», «подробнее») уходит
  в пользовательское сообщение, иначе кэш обнуляется на каждом запросе.
- **Ответ модели — строгий JSON** (`output_config.format`), схема в `prompts.RESPONSE_SCHEMA`.
  Разбор всё равно устойчив к обёртке в текст: модель может ответить и без structured outputs.
- **Счётчик месяца сбрасывается лениво**: у пользователя хранится `quota_month`
  (первое число), и при первом обращении в новом месяце счётчик обнуляется. Крон не нужен.
- **Запрос к модели идёт вне транзакции БД** — держать транзакцию открытой 15 секунд
  нельзя. Из-за этого при двух одновременных сообщениях лимит можно перебрать на единицу;
  частоту ограничивает rate limiter.
- **Квота списывается только после успешного ответа.** Упал API — пользователь
  ничего не потерял.
- **Кнопки «Другой вариант» и «Подробнее» — это новые запросы к модели**, поэтому они
  списывают лимит так же, как обычное сообщение.

## Оплата

Провайдер не подключён: `/pay` и кнопка «Оплатить Pro» отвечают, что онлайн-оплата
ещё подключается. Всё, что вокруг оплаты, уже на месте:

- таблица `payments` с уникальным `external_id` — повторный callback не задвоит оплату;
- `repo.activate_pro()` — активация и продление подписки (Pro поверх активной
  подписки продлевает её, а не перетирает);
- `app/payments/base.py` — интерфейс `PaymentProvider` и `DisabledProvider`.

Чтобы включить Payme, нужно: реализовать `PaymeProvider.create_invoice`, добавить
роут для callback'ов (`CheckPerformTransaction` / `PerformTransaction`), который
вызывает `record_payment` + `activate_pro`, и поставить `PAYMENT_PROVIDER=payme`.
Остальной код не меняется.

Пока эквайринга нет, доступ Pro выдаётся вручную: `/grant <tg_id> [дней]` от админа.

## Метрики

`/stats` (только для `ADMIN_IDS`) показывает за сутки и за 7 дней: новых пользователей,
запросы, долю жалоб «не сработало», расход Claude API в долларах, оплаты и выручку.
Для разовых срезов по этим же таблицам ставится Metabase поверх PostgreSQL.

Себестоимость каждого запроса пишется в `requests.cost_usd` с учётом кэша
(запись в кэш — 1.25× цены ввода, чтение — 0.1×), поэтому метрика «средняя
себестоимость запроса» считается прямо по таблице.

## Тесты

```bash
make test
```

42 теста, внешние сервисы не нужны: Claude API и Redis подменяются, репозиторий
и сценарий гоняются на sqlite in-memory. Покрыты лимиты месяца и частоты, разбор
ответа модели, расчёт себестоимости, отрисовка ответа, сценарий целиком
(пейволл, rate limit, отказ API не списывает квоту) и заглушка оплаты.
