### Что мы продаём: очень специфичные товары

- 30 категорий, 280+ SKU
- B2B-only: фарм/биотех/мед предприятия
- Средний чек: $5k-200k (от расходников до проекта gowning room)
- Длинный цикл сделки: 2-12 недель
- Узкая аудитория: ~50-100 предприятий в Узбекистане + ~10-20 в Pharma Park

### Это значит для SEO

**Не работает:**
- Гонка за высокочастотными общими запросами («перчатки», «дезинфектанты») — там marketplaces и B2C
- Любые транзакционные шаблоны «купить дёшево», «оптом» без B2B-контекста
- Generic «купить в Ташкенте» без специфики

**Работает:**
- **Длинный хвост (long-tail) с высокой конверсией** — «нитриловые перчатки стерильные для GMP A/B купить Ташкент»
- **Контент-экспертиза** — посты про Annex 1, валидацию, GMP-2027, аудиты
- **Калькуляторы** — уникальный механизм захвата лида + SEO-точка входа
- **Локальная привязка** — Pharma Park, узбекистанские поставщики, АРФО
- **Авторитетность темы (E-E-A-T)** — Google любит сайты, которые глубоко знают свою нишу

## 2. Семь стратегических принципов

### Принцип 1 — Брать только то, где можем выиграть

Целимся в запросы с конкуренцией **low** или **medium**. Запросы с high competition (где marketplaces + аптеки) игнорируем — туда нет B2B-intent.

### Принцип 2 — Каждая категория = pillar страница + 3-7 спутников

```
PILLAR: /catalog/disinfectants-and-detergents (главная страница категории, 800-1500 слов)
  ├── /catalog/disinfectants-and-detergents/filter/sterile (facet)
  ├── /catalog/disinfectants-and-detergents/filter/sporicide (facet)
  ├── /resources/disinfection-validation-protocol (lead magnet)
  ├── /tools/disinfectant-calculator (tool)
  ├── /blog/vybor-dezinfektantov-dlya-farmacevticheskogo-proizvodstva (blog post)
  ├── /blog/rotaciya-sporitsidov-annex-1 (blog post — NEW)
  └── /compliance/annex1 (compliance reference)
```

Все спутники ссылаются на pillar. Pillar ссылается на ключевые спутники. Это даёт **topical authority** для Google: «этот сайт реально знает про дезинфектанты для cleanroom».

### Принцип 3 — Узбекистан в каждом title

Title-шаблон для категорийных страниц:
```
{seoH1} в Узбекистане — купить для GMP / ISO 14644 в Ташкенте
```

Для блог-статей и lead-магнитов:
```
{topic} для фарм-производств Узбекистана | Clean Room Systems
```

Это даёт +30-40% к UZ-видимости даже без других правок.

### Принцип 4 — Calculator-first lead generation

Калькуляторы — наш единственный дифференциатор от IBC Nanotex. Дополнить с 3 до 6:
- ✅ Расход перчаток
- ✅ Расход дезинфектантов
- ✅ Бюджет gowning room
- 🔜 Расход салфеток (на основе калькулятора дезинфектантов)
- 🔜 Расход стерильных костюмов (по сменам)
- 🔜 ROI многоразовая vs одноразовая одежда (комплексный аналитический)

Каждый калькулятор = отдельная SEO-страница + lead-форма.

### Принцип 5 — Контент-фабрика 1-2 поста в неделю

Догнать IBC Nanotex по объёму контента (98 статей). Сейчас у нас 21. **Цель Q4 2026 — 60 статей, Q2 2027 — 100.**

Не «писать ради количества». Каждая статья должна:
- Отвечать на конкретный B2B-вопрос (часто из реальных диалогов с клиентами)
- Иметь H1 совпадающий с целевым запросом
- Ссылаться на 3-5 страниц каталога/calculator/resources
- Содержать FAQ-схему

### Принцип 6 — Локальный авторитет (E-E-A-T)

Google ранжирует сайты, которые «реально существуют в стране». Сигналы:
- Юр. лицо (ООО TOPAZ COMPANY) — на странице about
- Узб. адрес (ул. Нукус, 85/1, Ташкент)
- Узб. номер (+998)
- Сертификаты партнёров (Contec, Terragene)
- Кейсы с узбекскими клиентами (даже анонимные — «фарм-завод в Зангиате, 200 сотрудников»)
- Профили на Pharma Park, торговых каталогах UZ
- LinkedIn-страница с UZ-локацией
- Telegram-канал

### Принцип 7 — Технический SEO — фундамент

- ✅ Static export, быстрый рендер
- ✅ Sitemap включает 404+ URLs
- ✅ Schema (Product, ItemList, FAQPage, BreadcrumbList, BlogPosting, WebApplication)
- ✅ Canonical
- ⚠️ HTML страниц `/resources/*` тяжёлые (370+ KB) — оптимизация позже
- ⚠️ JS-бандл 347 KB — lucide-react import дробить
- 🔜 Cloudflare proxy для UZ-edge (TTFB 1.5s → 0.4s)

## 4. Технический SEO — что сделать

### Уже сделано (✅)
- Sitemap.xml (404 URLs, обновляется автоматически при build)
- robots.txt с ссылкой на sitemap
- Canonical на всех страницах

- Schema.org: Product (без Offer для B2B), ItemList, FAQPage, BreadcrumbList, TechArticle, BlogPosting, WebApplication, Organization
- Verification: Google Search Console + Яндекс.Вебмастер
- GTM + GA4 + Метрика + Tawk
- WebP + AVIF для всех изображений
- Static export, быстрая отдача с Vercel
- Brand normalization
- 280+ SKUs в индексе с уникальными title/description

### К доработке (⚠️)
- **JS-бандл 347 KB** (419 chunk) — оптимизировать импорты lucide-react (барелл-импорт грузит всё). Эффект: -100-150 KB, ускорение TBT.
- **HTML `/resources/gmp-audit-checklist` 373 KB** — самый тяжёлый. Разбить на 2-3 связанных URL или lazy-load FAQ.
- **TTFB 1.4-2s из UZ** — Vercel fra1 далеко. Включить Cloudflare proxy (бесплатно). Эффект: TTFB 1.5s → 0.4s.
- **Hreflang** — сейчас x-default = ru-RU. Когда добавим UZ и EN-версии, нужно прописать hreflang для каждой страницы.
- **301 redirects** — настроить redirects со старых URLs (если есть)
- **Image alt-tags** — пробежаться, особенно по `/catalog/*/[product]/page.tsx` (там alt = product name, но проверить)
- **Core Web Vitals** — после оптимизации замерить через PageSpeed Insights (квота API закрыта, нужно вручную через https://pagespeed.web.dev/?url=https://cleanroom.uz/)

### Новое (🔜)
- **Structured data: HowTo** для статей-инструкций (например, «Как валидировать программу дезинфекции в 4 шага»)
- **VideoObject schema** — если запишем 2-3 видео-разбора (TINMAN сборка, расчёт расхода)
- **LocalBusiness expansion** — добавить openingHours, paymentAccepted, currenciesAccepted на /contacts
- **AggregateRating** — если запустим систему отзывов клиентов (требует фактических отзывов; не подделывать)

## 13bis. Penalty prevention (защита от санкций поисковиков)

Главное правило: **рост через качество, не через объём**. Все массовые операции делаем с гардами.

### Риск 1 — AI-generated content (главный риск, 2024+)

**Контекст:** Google's Helpful Content Update (март 2024) и последующие апдейты понижают сайты с массовым низкокачественным AI-контентом. ~80% контента, который мы публикуем за последние недели — генерируется Claude-агентами по структурированным брифам.

**Что нас защищает:**
- Контент нишевый и фактологический — §§ Annex 1, ICH Q-серия, конкретные SKU
- Каждая статья решает конкретный B2B-вопрос
- Не «AI generic copywriting» — а агенты с экспертным брифом

**Дополнительные guardrails (обязательно):**
- **Human review каждой новой страницы** — CEO или технический эксперт пробегается перед публикацией (15 мин на статью). Минимум: проверить факты по стандартам + отсутствие маркетинговых клише
- **E-E-A-T-сигналы** — добавить страницу `/about/team` с реальными людьми (имя, фото, должность, экспертиза). Под каждой статьёй — подпись «Автор: …, QA-эксперт CRS»
- **Уникальные factual datapoints** — каждая статья должна содержать данные, которых нет нигде: реальные UZ-кейсы, конкретные цифры партий, фото с площадок
- **Раз в месяц — премиум-статья вручную** — глубокий разбор с экспертным интервью. Отличает сайт от AI-фермы

### Риск 2 — Facet pages как «doorway pages»

**Контекст:** Google квалифицирует страницы, созданные **главным образом для SEO** с тонким уникальным контентом, как doorway pages. Это grounds для алгоритмического снижения.

**Что нас защищает:**
- Каждая facet (`/catalog/{cat}/filter/{slug}`) имеет уникальный H1, title, meta, intro 80-120 слов
- 7 facets имеют дополнительные H2-секции и FAQ
- В sitemap, доступны юзеру через UI

**Дополнительные guardrails:**
- **Минимум 3 продукта** на facet иначе `noindex` — если меньше, выгода для юзера нулевая
- **Мониторинг через GSC**: если facet получит флаг «Page is a duplicate» / «Soft 404» — немедленно `noindex` и анализ причины
- **Максимум 35-40 facets** общим количеством. Не наращивать в бесконечность
- **Контентный минимум** на каждый facet: ≥150 слов intro + 1 уникальный H2 OR 3 уникальных FAQ

### Риск 3 — Keyword stuffing (особенно geo-stuffing)

**Контекст:** Шаблон title `{seoH1} в Узбекистане — купить для GMP / ISO 14644 в Ташкенте` содержит и «Узбекистан» и «Ташкент». На грани **Баден-Бадена** (Яндекс) и Google over-optimization signal.

**Дополнительные guardrails:**
- **Варьировать гео-окончания**: 60% страниц с «в Узбекистане», 30% с «в Ташкенте», 10% без гео
- **Плотность ключа в тексте ≤2%** — то есть в статье на 1000 слов главный ключ повторяется максимум 15-20 раз
- **LSI-синонимы**: вместо повторения «дезинфектанты» → «средства дезинфекции», «дезинфицирующие препараты», «обеззараживающие средства»
- **Естественный язык важнее точного match** — Google понимает синонимы

### Риск 4 — Manipulative cross-linking

**Контекст:** Если 30 категорий имеют блок «По теме» со ссылкой на одну и ту же compliance-страницу с одним и тем же анкорным текстом — это **манипуляция якорным текстом** в глазах Google.

**Дополнительные guardrails:**
- **Variety в анкорах**: не «GMP Annex 1» 30 раз, а «требования к чистоте», «правила одевания», «контроль контаминации» — разнообразные тексты на одну ссылку
- **Контекстуальные ссылки** (в тексте параграфов) работают лучше блоков ссылок в конце
- **Не каждая страница** ссылается на всех — связи должны быть тематически релевантные
- **Не использовать одинаковые анкоры** для коммерческих ссылок (`/catalog/...`) на разных страницах

### Риск 5 — Покупные ссылки (link farms)

**Контекст:** Google Penguin / Яндекс Минусинск — алгоритмические фильтры за неестественный ссылочный профиль.

**Что нас защищает (уже в стратегии):** явно запретили покупку ссылок. Все backlinks — органика.

**Guardrails:**
- **Disavow tool** — раз в квартал проверять backlinks в GSC, помечать спамные через disavow
- **Не участвовать** в link exchange схемах
- **Гест-посты только на качественных площадках** (DR>30, релевантная тематика, реальная редакция)

### Риск 6 — Низкие Core Web Vitals (демоутион)

**Контекст:** Google использует Page Experience signals — LCP, CLS, INP — как ranking factor. Сайт с плохими CWV проигрывает в выдаче, даже при хорошем контенте.

**Что есть проблемы:**
- `/resources/gmp-audit-checklist` 373 KB — тяжёлый HTML
- JS-бандл 347 KB (lucide-react barrel import)
- TTFB 1.4-2s из UZ (Vercel fra1)

**Действия Q3 2026:**
- Lazy-load FAQ-секций (через `<details>` open=false ↦ HTML всё равно грузится, нужен React lazy)
- Cloudflare proxy для UZ-edge → TTFB 0.4s
- Сжать самые большие webp (3-5 файлов ~150 KB сократить до ~50 KB)
- Замерять PageSpeed Insights раз в неделю; цель: Performance score ≥80 mobile

### Риск 7 — Cloaking (показ разного контента боту и юзеру)

**Защита by design:** static export, один HTML для всех. Не делаем. ✅

### Риск 8 — Yandex-specific фильтры

Узбекистан = 95% Google, 5% Yandex. Но для тех 5% есть отдельные фильтры:

- **АГС** — за low-quality контент / переоптимизацию. Защита: уникальный фактологический контент, человеческий тон
- **Минусинск** — за неестественные backlinks. Защита: не покупать
- **Баден-Баден** — за keyword stuffing. Защита: ≤2% плотность, LSI-синонимы
- **Турбо-сайт** — Яндекс предпочитает турбо-сайты в мобильной выдаче. Стоит ли заводить? — посчитать ROI отдельно

### Риск 9 — Auto-generated multi-language content

**Контекст:** Google наказывает за машинно-переведённые без редактуры страницы. Когда добавим UZ + EN-версии, это критичный риск.

**Guardrails (для Q4 2026):**
- **Финальная ручная редактура** носителем языка (узб./eng) — не пропускать
- **Хотя бы 30% уникального контента** в локализованной версии (не просто перевод — но переведённые акценты, локальные кейсы)
- **Hreflang corrlctly прописать** — иначе Google может посчитать клоны
- Если ресурсов не хватит на полную локализацию — лучше **не запускать UZ/EN-версию**, чем запускать машинный перевод

### Мониторинг и реактивные действия

**Раз в неделю (через `/week`):**
- Проверять GSC → Manual Actions (раздел в Security & Manual Actions)
- Проверять GSC → Security Issues
- Проверять Indexed pages count — резкое падение >20% = тревога
- Проверять резкое падение clicks/impressions >30% week-over-week

**Раз в месяц:**
- Полный аудит backlinks через Ahrefs/SEMrush
- Disavow подозрительных ссылок
- Анализ топ-10 страниц по падениям позиции
- PageSpeed Insights replay для топ-20 URL

**Если получили penalty:**
- Не паниковать
- Найти причину через GSC Manual Actions (если ручной penalty)
- Если алгоритмический — анализировать какой апдейт пришёлся на даты падения
- Reconsideration request только после исправления

### Главный принцип

**Делать контент для людей, не для поисковиков.** Если статья реально помогает QA-инженеру на узбекистанском фарм-заводе принять решение — ни один penalty не сработает. Если статья сделана только ради ключа — рано или поздно Google это поймёт.
